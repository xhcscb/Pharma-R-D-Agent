# 系统映射研究协议 v1.0

## 1. 协议状态

- 冻结日期：2026-08-05
- 检索截止：2026-08-04
- 方法：系统映射研究 + 核心论文深读
- 规范参考：PRISMA 2020、PRISMA-S、Kitchenham & Charters、Wohlin 滚雪球方法
- 变更原则：协议冻结后，任何检索式、筛选标准或评分规则的变化必须记录原因、日期、发起者和影响范围。

## 2. 研究问题

RQ1–RQ8 的正式定义见阶段总计划。筛选表中的 `research_question` 必须至少映射一个 RQ。

## 3. 检索协议

### 数据源层级

1. 同行评审主来源：ACL Anthology、NeurIPS、ICLR/OpenReview、ACM、IEEE、PubMed。
2. 综合索引：Web of Science、Scopus、Semantic Scholar、Crossref。
3. 预印本：arXiv；仅在无正式版本或研究非常近期时作为主记录。
4. 中文来源：CNKI、万方。
5. 标准：W3C、NLM、ClinicalTrials.gov 等官方站点。

### 日期和语言

- 主检索时间为 2018-01-01 至 2026-08-04。
- 基础标准和经典方法不受起始年份限制。
- 中文和英文分别执行检索，不互相替代。

### 日志要求

每次查询必须填写 `search_log.csv`。修改后的查询是新记录，不覆盖旧记录。导出文件只保存在忽略目录 `research/search/raw_exports/`，其哈希可记录到日志中。

## 4. 试检索与种子召回

- `seed_set.csv` 中 `is_seed=true` 的论文组成召回测试集。
- 试检索必须在允许的数据库组合中召回全部种子。
- 若某数据库无法覆盖跨学科种子，允许使用预先声明的数据库组合计算召回率，但必须记录每篇种子的命中来源。
- 召回率公式：`retrieved_seed_count / total_seed_count`。
- 只有召回率达到 1.00 才能将试检索状态改为 `passed`。

## 5. 纳入标准

候选研究必须满足以下相关性条件之一：

- 金融文档理解、比较、摘要、数值推理或评价；
- 与本项目任务相适配的数据集或基准；
- 知识图谱、本体、分层检索或图增强生成；
- PDF 版面、表格、图表、公式或脚注解析；
- Agent/多 Agent 的协作、工具调用、轨迹或评测；
- 数据集、系统综述和可复现研究的权威规范。

并同时满足：来源与版本可确认、至少一个 RQ 直接相关、能获取足够的方法/数据/实验信息。

## 6. 排除标准和原因码

| 代码 | 原因 |
|---|---|
| E01 | 与 RQ1–RQ8 均无直接关系 |
| E02 | 只有宣传、新闻或观点，没有方法/数据依据 |
| E03 | 纯股价预测且不涉及文档理解或投研推理 |
| E04 | 纯临床诊断且不能迁移到投研数据/知识任务 |
| E05 | 重复记录或已有更正式版本 |
| E06 | 作者、来源或版本无法确认 |
| E07 | 全文信息不足以评价方法或结果 |
| E08 | 非中文/英文且无可靠译文 |
| E09 | 已撤稿或存在未解决的重大完整性问题 |
| E10 | 其他；必须在 `decision_note` 中具体说明 |

不允许使用单独的“无关”作为全文排除理由。

## 7. 筛选流程

1. 去重后分配 `literature_id`。
2. 50 篇校准样本由所有成员独立判断。
3. 标题/摘要阶段至少随机抽取 25% 双人复核。
4. 全文纳入/排除 100% 双人复核。
5. 分歧由第三人裁决。
6. 使用 Cohen's κ；κ<0.70 时暂停并重新校准。
7. 15 篇锚点全部进入深读和前向/后向滚雪球。

允许状态：`pending`、`include`、`exclude`、`borderline`、`adjudication_required`。

## 8. 质量评价

七项各 0–2 分：任务定义、数据来源、方法描述、基线、指标有效性、实验可信度、开放与局限。

```text
quality_score = task + data + method + baseline + metric + experiment + openness
```

- 11–14：`core`
- 8–10：`supplementary`
- 0–7：`background`
- 权威标准：可设 `foundational_standard`，必须注明不适用的实验维度。

质量分数必须由全文阅读者填写并由复核者确认。

## 9. 证据提取

字段契约以 `literature_matrix.csv` 表头为准。缺失数据留空，不写 `N/A`。多个主题、RQ、项目组件或指标用英文分号分隔。

任何可进入专题结论的研究必须记录：

- 任务和数据来源；
- 方法及基线；
- 指标和主要结果；
- 消融或误差分析状态；
- 局限；
- 对项目的设计含义；
- 原文定位信息。

## 10. 综合规则

- 先按主题簇做叙述性综合，再按项目组件做跨主题综合。
- 不直接合并定义不同的指标或数据集结果。
- 设计决策需要至少 3 篇相互独立的支持研究。
- 每项设计决策必须记录至少 1 个反例、局限或替代方案。
- 预印本、同行评审论文和官方标准在综合中分别标记。
- 不以单个 LLM 裁判分数作为唯一证据。

## 11. 协议偏差记录

偏差记录至少包含：`deviation_id`、日期、原规则、新规则、原因、受影响记录、批准者。协议偏差不得静默修改历史数据。
