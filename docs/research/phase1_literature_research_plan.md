# 第一阶段：文献调研与研究设计冻结计划

版本：v2.1
周期：2026-08-05—2026-09-15（6周）
团队：5人
状态日期：2026-08-09

> 执行变化：数据层工程已根据后续项目要求提前并行实现。第一阶段研究的目标和质量门不变；现有实现只能作为待验证机制和实验载体，不能替代正式检索、全文复核、Gold 标注或 D01—D10 冻结。该变化记录在 `research/protocol_deviations.csv`。

## 1. 一句话说明

本阶段只做两件事：

1. 系统调查“别人如何做、如何评价、有哪些不足”；
2. 根据文献证据，确定本项目后续的数据、指标、机制和实验方案。

本阶段的研究交付物仍然是论文证据、指标和实验设计，不以新增工程功能作为完成标准。数据层即使已经可运行，仍须接受本阶段冻结的指标、基线和 Gold 语料验证。

## 2. 六周后必须得到什么

六周结束时，团队必须能够用文献证据回答以下问题：

- Compare Agent具体比较什么，怎样判断比较结果正确、完整且公平？
- Summarize Agent怎样区分共识、分歧、冲突和待验证信息？
- Metric Ontology、Claim Graph和Evidence Gate分别解决什么问题？
- PDF解析、知识图谱和Agent系统应选择哪些基线？
- 后续实验需要什么数据、怎样标注、用什么指标验收？

### 2.1 可验收目标

| 目标 | 最终产物 | 完成标准 |
|---|---|---|
| G01 检索可复现 | 检索协议、检索日志、PRISMA流程表 | 每次检索都有数据库、完整检索式、日期、结果数、执行人和导出记录 |
| G02 文献覆盖充分 | 证据矩阵 | 收录不少于100篇；七个主题都有覆盖；重复率抽查低于2% |
| G03 核心论文真正读懂 | 深读卡片 | 不少于40篇；其中15篇锚点论文完成双人复核；结果数字可定位到原文 |
| G04 评价指标可计算 | 指标登记表 | 每项指标写清定义、公式、Gold标注、聚合方法、适用任务和来源 |
| G05 关键机制有依据 | 七主题综合、研究假设 | 每项核心机制有不少于3篇独立研究支持，并记录至少1个反例或局限 |
| G06 研究设计可执行 | D01—D10决策记录 | 每项决策已冻结、驳回或明确标记“需要实验决定”，不存在含糊的待讨论项 |
| G07 第二阶段可启动 | 数据层需求包 | 明确数据来源、许可、Gold PDF抽样、标注字段、解析指标、基线和验收门 |

## 3. 范围边界

### 3.1 本阶段要做

- 检索中英文论文、数据集论文、技术报告和官方标准；
- 记录检索、去重、筛选和排除过程；
- 阅读核心论文，提取数据、方法、指标、实验结果和局限；
- 比较不同方案，并形成研究假设；
- 冻结后续数据层和Agent实验所需的研究设计。

### 3.2 不计入本阶段验收的工作

- 数据源接入、PDF解析器、数据库和可视化的代码数量不计作文献调研进度；
- 已实现的实体、关系和冲突机制不能在缺少论文证据和 Gold 测试时直接冻结；
- 不因已有实现而跳过简单基线、消融或失败条件分析；
- 本阶段不以实现 Compare Agent 或 Summarize Agent 作为交付条件；
- 不下载、共享或提交未授权的券商研报和论文PDF；
- 不把尚未人工核验的LLM摘要当作研究结论。

## 4. 需要统一理解的四个概念

| 概念 | 简单解释 | 本项目中的用途 |
|---|---|---|
| 证据矩阵 | 把每篇论文的任务、数据、方法、指标、结果和局限放在同一张表里 | 横向比较论文，避免只写读后感 |
| 锚点论文 | 每个主题中最关键、会影响项目设计的论文 | 作为滚雪球检索和双人深读起点 |
| 深读卡片 | 一篇论文的结构化阅读记录 | 保存原文定位、实验结果、局限和可复用内容 |
| 决策冻结 | 根据证据明确选择方案，或明确交给后续实验比较 | 防止进入开发后反复改变任务和指标 |

## 6. 总体执行流程

论文状态按以下顺序变化：

`identified → deduplicated → title_abstract_screened → fulltext_decided → quality_scored → extracted → verified → synthesized`

出现分歧时进入：

`borderline → adjudication_required → include / exclude`

## 7. 每一步具体怎样做

### 7.1 试检索

1. 成员1把18篇种子分配到对应主题和预期数据库。
2. 各主题负责人使用 `query_catalog.md` 中的标准式改写数据库语法。
3. 每次查询都新增日志行，不覆盖旧查询。
4. 在 `seed_set.csv` 填写每篇论文的实际命中来源。
5. 计算“全部数据库组合”的种子召回率。
6. 未达到100%时，先补同义词和字段，再重新试查。

试检索不是为了收集大量论文，而是验证检索式不会漏掉已知重要论文。

### 7.2 正式检索

每条检索记录必须包含：

- 数据库；
- 实际执行的完整检索式；
- 执行日期；
- 年份和语言限制；
- 命中数量；
- 执行人；
- 导出文件名和SHA-256；
- 查询版本和备注。

同一个数据库修改检索式时，创建新 `search_id`，不得覆盖历史记录。

### 7.3 去重

按以下顺序判断是否为同一论文：

1. DOI相同；
2. ACL、PubMed、arXiv等来源ID相同；
3. 规范化标题相同；
4. 标题高度相似且第一作者、年份相同。

预印本和正式论文同时存在时，保留正式版本，预印本作为关联版本记录。人工确认后才可删除重复记录。

### 7.4 标题与摘要筛选

每条记录回答三个问题：

1. 是否直接对应至少一个RQ？
2. 是否提供方法、数据、指标、实验或权威规范？
3. 是否能获得足够信息继续评价？

三个问题均为“否”时排除；信息不足时标记 `borderline`，不得凭印象排除。

### 7.5 全文筛选

- 所有全文由两人独立判断；
- 排除必须选择E01—E10，并写一句具体理由；
- 两人结论不同则进入第三人裁决；
- 无法获取全文的论文记录为E07或 `metadata_only`，不得猜测结果；
- 锚点论文原则上进入深读；若排除，必须由全组确认。

### 7.6 质量评价

每篇论文按七项各0—2分：任务定义、数据来源、方法描述、基线、指标、实验可信度、开放与局限。

- 11—14分：核心证据；
- 8—10分：补充证据；
- 0—7分：只作背景；
- 官方标准可标记 `foundational_standard`。

两名评分者先独立评分。总分相差超过2分，或任一单项相差2分时，必须讨论并给出最终一致分数。

### 7.7 深读卡片

每张卡片必须回答：

- 论文解决什么问题；
- 使用什么数据，数据如何获得；
- 方法由哪些步骤组成；
- 与哪些基线比较；
- 使用什么指标；
- 主要结果是什么，位置在哪里；
- 有哪些消融和错误分析；
- 作者承认哪些局限；
- 本项目可以复用什么，不能照搬什么；
- 影响D01—D10中的哪些决策。

只有第二人核对主要结论、数字和原文位置后，卡片状态才能改为 `full_text_verified`。

### 7.8 证据综合

综合采用两轮：

1. **主题内综合**：分别总结A—G七类研究的共识、差异和不足；
2. **跨主题综合**：把结论映射到Data Layer、PDF Parser、Metric Ontology、Claim Graph、Evidence Gate、Compare Agent、Summarize Agent、Agent Orchestration和Evaluation。

每条综合结论使用稳定编号，并列出：支持文献、反例或局限、适用条件、项目含义和置信度。

## 8. 六周时间表

### Week 1：协议与校准（8月5日—8月11日）

本周目标：证明检索式能找到已知论文，并让5人使用同一套筛选标准。

任务：

- 完成18篇种子和15篇锚点核验；
- 在各数据库执行试检索；
- 填写种子命中来源；
- 抽取50篇不同主题和边界情况的样本；
- 5人独立筛选并计算一致性；
- 修订含糊的纳入排除规则。

本周输出：检索日志、种子召回报告、校准日志、协议v2.1或新的协议偏差记录。

退出门：种子召回100%；平均两两κ≥0.70；协议得到组会确认。

### Week 2：正式检索与去重（8月12日—8月18日）

本周目标：建立完整、可追溯、无明显重复的候选文献库。

任务：

- 执行七主题的中英文正式检索；
- 保存每次查询和导出哈希；
- 合并预计400—800条原始记录；
- 按四级规则去重并分配文献ID；
- 随机抽查50组去重结果。

本周输出：正式检索日志、原始导出清单、去重后的候选主表。

退出门：每个RQ至少有2类数据源；去重后预计300—600条；抽查错误率<2%。

### Week 3：筛选与滚雪球（8月19日—8月25日）

本周目标：从候选记录中确定真正进入证据分析的论文。

任务：

- 完成全部标题/摘要筛选；
- 随机25%双人复核；
- 对初筛保留论文执行全文双审；
- 对15篇锚点执行前向、后向和作者滚雪球；
- 裁决分歧并更新PRISMA表。

本周输出：筛选决策表、排除原因统计、PRISMA流程表、滚雪球新增记录。

退出门：100—140篇进入证据矩阵；全文排除原因完整；所有分歧已裁决。

### Week 4：质量评价与深读（8月26日—9月1日）

本周目标：把“收集到论文”转化为“理解论文证据”。

任务：

- 5人各主读约8篇；
- 完成40篇结构化卡片；
- 15篇锚点完成第二人复核；
- 双人完成质量评分；
- 补齐矩阵的数据、方法、指标、结果、消融和局限字段。

本周输出：40篇卡片、质量评价表、完整证据矩阵。

退出门：40篇卡片通过复核；矩阵关键字段缺失率<5%；所有主要数字有原文位置。

### Week 5：综合、指标与研究假设（9月2日—9月8日）

本周目标：从单篇论文结论形成项目层面的设计依据。

任务：

- 完成A—G七主题综合；
- 建立Compare、Summarize和Agent指标表；
- 建立错误类型、基线和消融候选库；
- 为每项机制整理支持证据和反例；
- 将候选研究空白写成可证伪假设。

本周输出：主题综合、指标表、基线表、错误分类、正式候选假设。

退出门：每项机制≥3篇支持证据且有反例/局限；每项指标都能实际计算。

### Week 6：决策冻结与阶段验收（9月9日—9月15日）

本周目标：把文献结论转化为第二阶段可直接执行的研究设计。

任务：

- 逐项处理D01—D10；
- 用三类模拟任务检查任务、指标和图结构；
- 完成Gold PDF抽样与标注要求；
- 完成解析、检索和Agent基线及消融要求；
- 运行仓库校验，完成组内审核。

本周输出：决策记录、第二阶段数据需求包、研究空白与假设、验收报告。

退出门：矩阵≥100、深读≥40、锚点复核=15；D01—D10均有明确状态；校验通过。

## 9. 团队分工与协作方式

### 9.1 固定职责

| 成员 | 主责 | 每周固定责任 |
|---|---|---|
| 成员1 | 综述方法、数据集写作、质量控制 | 检查日志和PRISMA；主持筛选校准；维护协议 |
| 成员2 | 金融基准、数值推理、评价指标 | 维护指标表；检查计算定义和Gold标注需求 |
| 成员3 | PDF、表格图表、数据层需求 | 维护文档类型、解析指标和Gold PDF要求 |
| 成员4 | 知识图谱、本体、分层检索 | 维护Metric Ontology和图检索基线 |
| 成员5 | Compare、Summarize、Agent评测 | 维护任务边界、Claim Graph、Evidence Gate和Agent指标 |

### 9.2 交叉复核

固定复核链：

`成员1 → 成员2 → 成员3 → 成员4 → 成员5 → 成员1`

专题负责人不能独立批准自己的最终结论。关键结论、锚点论文和D01—D10必须至少由第二人确认。

### 9.3 每周协作节奏

- 周一：30分钟任务分配，确定本周数量和负责人；
- 周三：30分钟质量抽查，只讨论检索遗漏、筛选分歧和字段问题；
- 周五：60分钟阶段评审，决定是否通过本周质量门；
- 每次工作后：当天更新CSV或卡片并提交Git，不在个人聊天中保存唯一版本；
- 发现协议问题：先记入 `protocol_deviations.csv`，再讨论是否修改。

## 11. D01—D10怎样冻结

每项决策必须依次完成：

1. 写清要解决的问题；
2. 列出至少两个候选方案；
3. 列出支持证据和反例；
4. 用模拟任务检查能否表达和评价；
5. 选择 `frozen`、`experiment_required`、`rejected` 中一种状态；
6. 记录采用方案、理由、风险、批准人和日期。

不能根据文献直接判断优劣时，不强行选择；应标记 `experiment_required`，并写清第二阶段的对照实验和判定指标。

## 12. 最终验收

### 12.1 数量门

- 证据矩阵≥100篇；
- 深读卡片≥40篇；
- 锚点论文双人复核=15篇；
- 七主题均达到最低覆盖要求。

### 12.2 质量门

- 种子组合召回率=100%；
- 校准平均两两κ≥0.70，任一复核对≥0.60；
- 去重抽查错误率<2%；
- 全文筛选100%双人判断；
- 矩阵关键字段缺失率<5%；
- 每项核心机制≥3篇独立支持证据，并有反例或局限；
- 每项指标都可由明确Gold标注计算。

### 12.3 三类模拟任务

1. 比较两家医药企业在同一时间窗口的研发管线；
2. 汇总多份研报对同一药物市场空间的共识与分歧；
3. 处理不同来源中的口径、日期或数字冲突，并输出证据和不确定性。

若当前任务定义、Metric Ontology、Claim Graph、Evidence Gate或指标无法解释任一模拟任务，对应决策不得冻结。
